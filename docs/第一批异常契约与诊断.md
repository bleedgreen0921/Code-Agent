# 第一批：异常契约与诊断

本批对应 [总计划](异常处理与执行一致性增强计划.md)，以 core_0005 与阶段六 245 项用例为基线。独立证据见 [验收记录](第一批异常契约与诊断验收.md)。继续使用标准 create_agent、原生 middleware、ToolMessage、checkpoint 及既有 Task/Run 发布事务，不增加模型/工具重试、观察退避、取消重试、验证器、自动重放、Task 恢复或工作区回滚。

## failure_info

公共定义见 [failure.py](../agent_service/failure.py)。严格、不可变的 Pydantic 模型拒绝额外字段。

| 字段 | 固定契约 |
|---|---|
| version | 整数 1，布尔值与浮点数拒绝 |
| code | 可信代码生成的稳定代码，最多 96 字符 |
| category | parameter / permission / transport / timeout / protocol / execution / quota / configuration / persistence / cleanup / verification |
| effect | not_dispatched / possible_partial / unknown / not_applicable |
| recovery | correct_arguments / reread / retry_observation / reconcile_original / stop |
| message | 固定模板，最多 512 UTF-8 字节，不使用异常原文 |

整个对象不超过 2 KiB。recovery 只描述建议，不授予重试或恢复权限。模型输出、远程消息、错误码子串均不参与分类。完整代码与模板的权威目录是 `failure.SPECS`；未知异常使用 EXECUTION_FAILED，保守表达效果未知。

| 事实/代码 | 效果与处理 |
|---|---|
| INVALID_TOOL_ARGUMENTS / PERMISSION_DENIED | 派发前拒绝，not_dispatched / correct_arguments |
| FILE_VERSION_CONFLICT | 原文件未发布修改，not_dispatched / reread |
| SHELL_COMMAND_FAILED / BACKGROUND_COMMAND_FAILED / MCP_WRITE_ERROR / MCP_TASK_EXECUTION_FAILED | 已派发操作失败，possible_partial / stop |
| COMMAND_TIMEOUT / RUN_TIMEOUT / BACKGROUND_TIMEOUT | 期限结束，unknown / reconcile_original |
| BACKGROUND_RECEIPT_INVALID / MCP_TASK_RECEIPT_INVALID / MCP_TASK_PROTOCOL_ERROR | 回执不合法，unknown / reconcile_original |
| MCP_RESULT_UNKNOWN / BACKGROUND_RESULT_UNKNOWN | 原结果未确认，unknown / reconcile_original |
| BACKGROUND_RESOURCE_IDENTITY_CHANGED / MCP_TASK_IDENTITY_CHANGED | 原身份不匹配，unknown / stop |
| HOOK_CONTRACT_ERROR | 执行边界契约被破坏，not_applicable / stop |
| PERSISTENCE_FAILED | 保存未确认，unknown / reconcile_original |
| RESOURCE_CLEANUP_FAILED | 原资源释放未确认；不改变操作已保存的执行效果 |

Run 的诊断描述其失败原因，不能据此声称整个 Run 从未产生副作用。QUEUED 超时使用 not_applicable；通用执行超时、失租和进程结束不能补造未执行结论。HTTP 错误不能证明远程写入没有发生。操作变为 unknown 时，即使触发原因是配置变化，其效果仍为 unknown。模型/配置本身的 Run 故障可使用 not_applicable。

工具诊断放在标准 `ToolMessage.artifact.failure_info`。诊断预算优先于其它 artifact/正文；结果保存与数据库确认重试复用同一份有界内容，不重新派发或重新分类。原生参数消息和调用计数保留。

取消、LangGraph 控制异常、执行失败、超时、限额、Hook 契约、数据库故障及包含它们的异常组保持传播。真实执行边界记录控制失败，外层 Hook 或原生错误中间件返回普通消息也不能将其吞掉。可恢复错误列表拒绝控制类型及其宽泛父类。

## 回执与身份

本地固定执行镜像回执必须完整包含 exit_code（严格整数）、timed_out/cancelled/truncated（严格布尔）、total_bytes（严格非负整数）、output（字符串）。禁止额外字段及同时超时和取消。先完整校验，再裁剪展示输出并计算状态；截断不改变执行结果。

非法回执默认 unknown / BACKGROUND_RECEIPT_INVALID。只有实际停止原容器并确认原容器已退出，才能沿用取消结果；此时诊断仍明确效果未知。取消意图、已发送请求和当前期限不能单独证明取消。非零退出保存 BACKGROUND_COMMAND_FAILED，允许已有部分效果。

Docker 身份、操作标签与实际依赖的状态字段先于停止/删除校验，已有 container ID 必须一致。MCP 继续使用锁定 SDK 模型及 outputSchema；持久句柄、创建回执、状态 task ID 必须一致，绑定包含 server/account/配置与凭据身份摘要。使用 SDK 已解析的 is_error；有界结果不裁掉单独持久保存的关联身份。无可靠句柄不重新提交。

## 操作状态与清理

普通更新、内部原事实补记与清理分别使用 `operation_update`、`operation_reconcile`、`operation_cleanup`，共享数据库守卫。没有 HTTP 或模型接口可选择事实补记入口。

| 当前状态 | 规则 |
|---|---|
| starting | running / cancelling / succeeded / failed / cancelled / unknown；相同提交可确认 |
| running | cancelling 或终态；禁止回 starting |
| cancelling | 保持取消中或进入终态；迟到 starting/running 保持 cancelling |
| succeeded / failed / cancelled | state/result/error_code/failure_info 不可覆盖；完全相同结果可确认 |
| unknown | 普通更新保护未知事实；内部权威观察可补记已确认终态 |

更新在既有串行化事务内读取当前数据库行，校验 monitor token 与期限，不能依赖调用方缓存。容器 ID、daemon、远程句柄、创建回执只首次绑定或确认相同值。取消意图不覆盖权威完成事实；Run/Task 仍使用既有发布优先级。相同状态但不同结果不算确认。重复确认不新增事件、不改完成时间。

同步外部普通保存只允许有效原授权下 dispatched → succeeded/error/unknown；失租后的迟到事实必须关联原派发并通过内部事实入口保存。终态同样比较完整 receipt/error_code/failure_info。

unknown 与所属 Task 失败在同一事务内提交。补记终态也先确保 Task 已保持失败或其它终态，只更新操作事实与事件；不调度、不消费结果、不更新成功历史，不改 Task/Run 终态或已发布 checkpoint。

cleanup_state=released 不可回退。清理失败只写清理字段，不能覆盖已确认的执行主错误；成功清理不代表撤销副作用。新清理说明使用固定安全代码/模板；历史自由文本不进入新摘要。

## 日志与只读摘要

API 的 `python -m scripts.serve` 与 Worker 的 `python -m agent_service.worker` 安装同一 JSON 格式器。日志保留既有用量/委派统计，字段白名单增加 task_id、run_id、operation_id、agent_id、call_id、tool_name、duration_seconds、result_type、status、error_code。后台事件关联原 Task 和来源 Run。

普通字符串最多 256 UTF-8 字节，整条 JSON 最多 16 KiB；超限固定先裁剪统计，再裁剪堆栈，标记 truncated。堆栈仅包含异常类型及文件、函数、行号，不包含异常消息、源码、局部变量、原始原因链。message 使用固定事件名，未知日志事件折叠为 log_event，不记录命令、工具参数、响应或凭据。序列化故障降级为固定安全事件，不影响执行。

Run/会话轮次/Task 详情增加 unresolved，doctor 增加全局同结构摘要：

| 字段 | 定义 |
|---|---|
| unknown_operations | 后台和同步外部 unknown 数 |
| unreleased_resources | 未释放 Run 执行资源数 + 后台清理未确认数 |
| oldest_age_seconds | 最老关联记录从创建时间起的秒数；空集合为 null |
| reasons | 稳定错误码或安全原因的关联记录计数 |
| records | 最老优先的身份、状态、时间、安全原因与计数标志，至多 50 条 |
| truncated | 关联记录是否超过 50 条 |

Task 汇总其全部 Run，Run 只看自身，doctor 全局。同步 unknown 不自动计入未释放；同一后台操作可同时贡献两个计数，records 只展示一次。reasons 按记录计数；历史非白名单错误折叠为 LEGACY_FAILURE，不推断历史效果。记录不包含命令、正文、凭据或 binding。

SQL 在 LIMIT 之前计算全量统计。详情主体与摘要共享 REPEATABLE READ READ ONLY 快照，不取 admission 锁，不调用 maintain、调度或外部观察。列表不逐条聚合。年龄不声称等于进入 unknown 后的精确时长。原提交模型、状态集合、答案和 HTTP 错误 envelope 保持兼容，trace/timeline 沿用原接口。

## 部署

停止旧 API/Worker → owner 运行 `python -m db.migrate` → `python -m db.bootstrap` → `python -m db.doctor --json` → 启动新进程。执行镜像在部署准备期重新构建并锁定不可变 ID。

core_0006 仅新增 runs/background_operations/external_operations.failure_info 三个可空 JSONB 列；数据库约束要求对象且不超过 2 KiB，完整结构由应用严格校验。无详情使用 SQL NULL。历史不回填、不分类、不清除未知记录、不释放未确认占用、不改 checkpoint。结构签名保留全部历史版本，结构漂移在 DDL 前拒绝，bootstrap/readiness 要求 core_0006；现有表级授权覆盖新增列，运行角色没有 DDL 权限。框架依赖锁定不变。
