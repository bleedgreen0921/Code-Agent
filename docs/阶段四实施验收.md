# 阶段四实施验收：受控子 Agent

2026-10-15。在已有 create_agent 循环内，以标准 delegate_read 工具就地等待原生只读子图。沿用锁定的框架版本与 PostgreSQL Checkpointer，无新增依赖、表或迁移，数据库仍为 core_0003。

## 交付行为

- 内置 workspace_read/workspace_write 默认启用委派，chat 仍为空工具且维持原绑定。自定义 Profile 显式选择 delegate_read 并具有至少一种工作区读取/搜索工具。唯一公开参数 task，严格非空、最多 8192 UTF-8 字节，拒绝其它字段。
- 每个实际 Run 使用独立 DelegationController，在启动前原子占用额度，最多两次且串行，只允许深度一层。已启动的成功/局部失败均消耗一次；非法输入、权限和批次拒绝不消耗，重复原调用 ID 不启动。摘要、Hook 丢弃 Command 状态或下一轮执行均不会错误恢复额度。
- 原生 middleware 在 Hook 前拒绝混合/多委派批次，执行入口在 Hook 后复查不可变的原批次与调用身份，普通工具仍照常执行。委派本身不持有工作区锁或命令计时器，子读取工具仍使用父 scope 的原锁、30 秒默认命令超时和输出限制。
- 子权限取父策略与 glob_search/grep_search/read_file/read_skill 固定白名单交集。重新实例化标准读取工具，权限绑定实际实例、保留所选参数校验器和同一技能白名单。无写入、Shell、Todo、自定义工具或再次委派。读写父容器的子图只读性来自受控工具，不宣称独立容器只读边界。
- 每次子图只输入一条本次 task 的 HumanMessage，不继承父消息、Todo、已读取技能正文、业务状态、结构化输出或扩展 Hook。冻结 RunContext 使用新 agent_id、父标识和深度 1，run_id/工作区绑定/总期限保持父 Run 值。
- 父图继续使用原生 16/10 限次；子图使用独立原生 8/6 限次。主循环总上限为 32 次模型、22 次工具调用，摘要额外调用依框架行为，不承诺硬 token 配额。
- 原生子配额耗尽、明确 SDK 模型失败与非法最终文本使用稳定脱敏工具错误反馈父图；父图可自行完成或用剩余一次委派。取消、总超时、失租、环境/命令故障、持久化/Hook 契约及未知异常向外传播。SDK 异常还必须确认为模型回调观察到的失败，子工具抛出的同类型异常不误分类为可恢复模型错误。
- 同 thread_id 使用框架生成的独立 namespace，通过 values/checkpoints 流和同步 durability 等待，确认无 next/interrupt、合法最终文本及明确 checkpoint 已落盘。父图只收到最终文本或错误，不合并子消息。父原生状态保存最多两条关联摘要，根最终发布和后续会话继承明确限定根 namespace。
- 根原生用量回调只挂载一次，观察父、子和摘要；子回调独立诊断，其数值不再加回根总量。缺失报告以完整性标记表示，异常日志补充不完整汇总，不建立逐调用账本。HTTP/CLI trace 支持精确 namespace 过滤，默认仍读全部。
- 子图无独立 Run、队列或额外 Worker 槽位，共用父容器、占用、取消与清理。Worker 强制退出后只终结失租 Run 并回收资源，不恢复子 checkpoint；持久化或发布确认丢失不重放模型/工具。
- 故障回归发现嵌套取消可打断 Docker 客户端的进程收尾；冻结后的 Run scope 现在会完成剩余客户端进程的终止和回收，再释放工作区占用，避免资源状态停留 closing。

测试入口为 `python -m scripts.postgres_integration`，真实隔离 PostgreSQL、真实 Docker、固定执行镜像与合成模型；严格禁止真实模型 HTTP，要求非空报告及零失败/错误/跳过。原有 99 项完整保留，新测试集中在 tests/test_delegation.py。
