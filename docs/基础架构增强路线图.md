# 基于 LangChain/LangGraph 的基础增强路线图

## 目标与实施原则

分为 **6 个阶段**，每阶段形成一次可独立验证的交付。**近期实施第 1～3 阶段，交付可靠的单 Agent 底座**；第 4～6 阶段按后续需求推进，复杂协作和自主长期运行暂缓。

- 继续使用标准 `create_agent`、LangGraph 状态与原生 PostgreSQL Checkpointer，沿用当前锁定的框架版本。
- 优先组合现成中间件、工具、存储及适配器；自写代码集中在权限、资源归属、配置衔接和业务验证。
- 每阶段只增加当前需要的接口与表结构，不提前建设通用插件平台、调度引擎或调用账本。
- 每阶段完成实现、迁移、测试和文档后，再进入下一阶段。

## 近期交付：可靠的单 Agent 底座

### 阶段 1：统一运行契约与扩展入口

**对应：s03 Permission、s04 Hooks、s15 Harness 集成。**

- [x] 扩展现有 Agent 工厂，支持原生提示词、middleware、自定义状态和结构化输出参数，保留标准工具及 Store 接口。
- [x] 建立可信运行上下文，统一传递工作区、能力配置和截止时间；配置由服务端解析，密钥与资源句柄不进入 checkpoint。
- [x] 使用原生 middleware 实现权限入口与工具前后扩展；权限判断覆盖最终执行参数，错误、取消和配额异常保留明确语义。
- [x] 记录脱敏的有效运行配置与版本，供 trace 诊断；采用单条 Alembic 核心迁移链承接当前基线，继续在修改前拒绝旧业务数据库。

**接口约定：**独立 Run 和会话创建支持可选的 `workspace_id`、`profile`；默认保持现有空工具行为。工作区和能力配置来自服务端注册，会话绑定后保持固定，轮次请求仍只提交 `task`。幂等比较覆盖完整有效输入。

**验收：**旧调用方式继续可用；标准合成工具通过统一策略执行；拒绝规则不能被 Hook 改写绕过；当前核心库能够升级，已有任务和 checkpoint 保持可读。

**验收记录：**[阶段一实施验收](阶段一实施验收.md)（32 项，零失败、零错误、零跳过）。

### 阶段 2：受控工具与执行环境

**对应：s01 Agent Loop、s02 Tool Use，以及 s13 中独立的工作区隔离需求。**

- [x] 提供三个明确配置：空工具对话、工作区只读、工作区读写与命令执行。只读配置不暴露 Shell。
- [x] 优先复用原生文件搜索和 `ShellToolMiddleware`；分段读取与小范围补丁使用标准工具补充，不建立新工具协议。
- [x] 命令使用 `DockerExecutionPolicy`，默认禁用网络，仅挂载指定工作区，不注入服务凭据。执行环境不可用时明确失败。
- [x] 将进程、容器和工作区占用绑定到 Run；成功、异常、取消、超时和失租均执行清理，确认清理后释放占用。同一工作区先采用单执行者策略。
- [x] 限制命令时间和输出，保留退出码、超时与截断信息；失败后的文件变更可检查，不承诺自动回滚。

默认单命令上限为 30 秒、输出上限为 16 KiB 或 200 行；继续保留现有任务总期限和全局容量。复用框架的执行策略与输出处理能力。[原生中间件说明](https://docs.langchain.com/oss/python/langchain/middleware/built-in)

**验收：**Agent 能在测试工作区搜索、读取、修改文件并执行命令；越界与只读写入被阻止；取消后无遗留执行进程；不同工作区隔离，同一工作区不会并发修改。

**阶段二验收记录：**[阶段二验收](../execution/ACCEPTANCE.md)（66 项，零失败、零错误、零跳过）。

### 阶段 3：复杂任务的上下文与进度

**对应：s05 TodoWrite、s07 Skill Loading、s08 Context Compact。**

- [x] 接入原生 `TodoListMiddleware`，复杂任务按需使用；Todo 属于当前 Run，不默认跨轮继承，也不作为验收依据。
- [x] 保留现有 `SummarizationMiddleware`，补充工具输出限量、可信约束重新注入和长上下文回归测试。
- [x] 增加轻量 Skill Loading：从服务端认可目录发现技能，先加载名称与描述，按需读取正文。技能内容不改变工具权限。
- [x] 建立状态继承白名单：继续继承成功轮次的消息；运行计数、进程资源和当前 Run 的待办不复制到下一轮。

**验收：**简单任务无需额外规划；多步骤任务可维护待办；技能正文按需加载；摘要后关键约束仍存在；失败、取消与不同会话之间不发生状态串用。

**阶段三验收记录：**[阶段三实施验收](阶段三实施验收.md)（99 项，零失败、零错误、零跳过）。

**近期完成标准：**单 Agent 能在明确权限和工作区内完成多步骤工具任务，执行可取消、过程可观察、状态可持久化。具体代码审查与修复规则可在此基础上独立增加。

## 后续交付：按需求启用

### 阶段 4：受控子 Agent

**对应：s06 Subagent。依赖阶段 1～3。**

- [ ] 通过标准工具调用子 Agent，使用独立消息与 checkpoint 标识，向父 Agent 仅返回最终文本。
- [ ] 首版仅提供只读委派：最多一层、串行执行、每个父 Run 最多两次；子图使用独立的原生调用限制。
- [ ] 继承父任务剩余期限和取消信号，权限取父任务允许范围的子集；记录父子关联和聚合用量。
- [ ] 在父执行内部完成同步委派，避免父任务占满顶层 Worker 槽位后等待排队子任务。

**验收：**父子消息隔离、权限不扩大、取消可传播、调用数量有界，并且不会因现有全局容量限制发生等待死锁。

### 阶段 5：项目知识与外部工具

**对应：s09 Memory、s14 MCP Plugin。依赖阶段 1～3，可独立于阶段 4 推进。**

- [ ] 使用标准 `BaseStore` 和原生 PostgreSQL Store，按工作区保存显式确认的项目知识；提供明确的保存、读取、检索和删除操作。
- [ ] 首版使用键、命名空间和元数据过滤，不启用 Embedding 或自动记忆提取；默认仍可关闭 Store。
- [ ] 使用官方 MCP 适配器接入静态配置的服务器，明确工具白名单、名称和连接生命周期。
- [ ] Memory 与 MCP 工具均进入已有权限、超时、输出限制及 trace 路径；新增依赖单独锁定并验证兼容性。[MCP 接入说明](https://docs.langchain.com/oss/python/langchain/mcp)

**验收：**项目知识跨 Run 可用且不串工作区；删除生效；MCP 断连或工具异常可诊断；外部工具不能绕过现有策略。

### 阶段 6：持久任务与后台操作

**对应：s10 Task System、s11 Background Tasks。依赖前述资源管理能力，出现跨 Run 长任务需求后启动。**

- [ ] 增加独立于 Run 的 Task：保存目标、依赖和完成状态；Run 继续表示一次有期限的执行。
- [ ] 扩展现有 PostgreSQL 原子认领机制，支持就绪依赖任务；固定流程复用 LangGraph 图编排。
- [ ] 后台操作归属于 Task，保存操作标识、执行资源、状态和结果位置，支持查询与取消。
- [ ] 等待后台结果时释放 Run 执行槽；结果到达后创建新的执行处理结果，不默认恢复或重放旧 Run。
- [ ] Worker 重启后先核对已有操作；结果未知时明确终结或等待处理，不重新执行可能已生效的命令。

**验收：**依赖任务不会提前运行；后台操作可查询、可取消；重启不重复执行；等待不会占满全部 Agent 槽位。

## 统一验证与交付要求

各阶段沿用同一验收入口：

- 运行原有及新增测试，真实 PostgreSQL 验证持久化与升级；工具阶段增加真实隔离容器测试。
- CI 使用合成模型、禁止真实模型 HTTP，报告非空且零失败、零错误、零跳过；缺少必要环境直接报告失败。
- 重点覆盖权限绕过、参数改写、输出截断、取消竞争、失租清理、状态继承和提交确认丢失。
- 每阶段更新配置、启动与故障诊断说明。真实模型冒烟单独运行，不以合成测试通过替代任务效果评估。
- 继续保留现有本机访问限制、数据库运行角色隔离和异常 Run 不自动重放的行为。

## 暂缓能力与启动条件

| 能力 | 当前处置 | 启动条件 |
|---|---|---|
| **s12 Cron Scheduler** | 暂不实现；未来作为向现有任务系统提交任务的触发器 | 已有稳定、需要周期执行的任务 |
| **s13 Agent Teams** | 暂缓队友消息、协作协议及自动合并；工作区隔离已提前覆盖 | 单 Agent 与受控委派出现明确瓶颈 |
| **s16 Workflow Runtime** | 保留原生 LangGraph 编排能力 | 出现重复、稳定且需要固定控制流的实际流程 |
| **s17 Goal Loop** | 完成检查通过现有扩展入口接入；独立 Judge 和持续自主循环暂缓 | 已有客观完成条件、可靠验证器及长任务反馈数据 |

近期先按顺序交付阶段 1、2、3。阶段 4～6 分别形成独立后续需求，进入对应阶段时再增加其持久化对象和运行机制。
