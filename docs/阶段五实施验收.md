# 阶段五：项目知识与外部工具实施验收

## 实施范围

在阶段四 139 项测试基础上实现人工管理、Agent 只读的项目知识与静态授权 HTTP MCP 读写工具，修复最终参数校验、非文本/artifact 输出、Store 批处理生命周期、子图资源继承和外部写入未知结果。运行配置、知识 API、目录导出、凭据和核对步骤见 [项目知识与外部工具](项目知识与外部工具.md)。

- 保留 LangChain 1.4.2、LangGraph 1.2.12、Checkpoint Postgres 3.1.2。FastAPI 0.143.1、Starlette 1.8.0；新增 fastmcp-slim[client] 4.0.1、MCP SDK 2.3.0、jsonschema 4.26.0。其余原有依赖版本保持锁定，完整锁文件重新生成；不安装 FastMCP server extras。
- knowledge.enabled 默认关闭；启用时生产图获得限定工作区、限定精确命名空间的只读标准 BaseStore 视图。拒绝写入/删除、命名空间枚举、跨命名空间、文本查询、比较操作符和越界分页；读取关闭 TTL 刷新。原生前缀搜索结果还会过滤子命名空间。可信工厂仍可接受标准 BaseStore。
- 项目知识使用原生 AsyncPostgresStore，没有新知识内容表、索引配置、Embedding、TTL 清理、正文缓存或自动写入。GET/PUT/DELETE 管理 API 通过强 ETag 前置条件和同事务 advisory lock 实现并发版本控制；管理写操作直接使用当前连接的原生 abatch，不进入后台队列。
- knowledge_get 返回当前条目/来源/版本，knowledge_search 只做顶层 category/source 等值分页；自定义 Profile 显式选择，内置工作区 Profile 在开启功能后增加只读工具，知识单独使用无需 Docker。删除不删除过去的 checkpoint/消息，也不自动恢复知识。
- MCP 采用原生 MCPAdapter 和固定 Streamable HTTP，API 仅加载本地 tools/list 目录。每 Run 独立客户端和 AsyncExitStack；模型前重新核对所选名称、说明、输入/输出 Schema、annotations，使用绑定实际客户端的工具实例。额外远端工具不自动开放，内置 Profile/子委派不自动获得 MCP。
- 可信本地校验器在 Hook 之后校验冻结 JSON Schema 和业务参数。模型批次在并行工具 Hook 之前冻结；MCP 写独占批次，初始入口和最终入口均检查，原调用 ID 不可换绑。无效参数不发送 RPC，工具错误关联原 ID。
- HTTP 保留 TLS，拒绝重定向和压缩响应，JSON 读取及 SDK SSE 事件在解析前限制 1 MiB。所选目录契约总量限制 32 KiB，文本和 artifact 有界，图片/音频/二进制只留类型，不下载资源。纯 structuredContent 转为可见 JSON 文本；已知凭据反射到输出会脱敏。
- 禁用响应缓存、sampling、roots、可选扩展、自动登录和自动工具重发；elicitation decline，要求续发 tools/call 的 input-required 结果直接失败。基础 initialize 会话协商与协议 GET 读取恢复保留。
- core_0004 只新增 external_operations；写请求先在有效租约下确认唯一派发记录，再发送 RPC。确认丢失只重试数据库，重复 Run/调用 ID 不派发。记录成功、明确错误、未知结果及有界回执；超时/断线/不可解析的写结果使 Run 失败，取消/失租/停止保留既有终态语义。
- 失效 Run 的未确认派发在维护时归为 unknown，不恢复工具执行；已确认成功不随 Run 失败回滚。trace、timeline、doctor 展示关联记录；没有审批、恢复、强制重试、跨 Run 恰好一次或后台对账接口，结果仍只有 answer。
- 退出先冻结调用、等待本地工作、关闭 MCP 连接，再清理容器和发布；清理期间续租，失败不能 completed。数据库核对失败也尝试关闭连接。MCP-only Run 无容器，未引用的服务不可达不影响 chat。
- 迁移 owner 在已有迁移锁下事务外初始化原生 Store，并验证版本和结构；已知初始化中断及无效并发索引可重跑修复，未知对象/结构/版本先拒绝。运行角色对所有版本表只有读取权限；服务不执行 DDL。原生 Store 批处理任务在数据库池关闭前显式收敛。

## 验证范围

统一入口 `python -m scripts.postgres_integration` 使用真实隔离 PostgreSQL 16、真实 Docker、固定执行镜像和合成模型。MCP 使用官方 SDK 服务，通过进程内 ASGI/受控 HTTP transport 完成握手、发现、适配、调用和关闭；网络禁令保持启用，不连接真实模型或外部业务 HTTP。

| 范围 | 核验内容 |
| --- | --- |
| 原有基线 | 升级依赖和公共边界后的独立 139 项基线全部通过；本机 Host/Origin、统一错误、checkpoint、取消、Docker 和运行角色权限继续覆盖 |
| 知识 API | 创建、更新、删除、ETag、428/412、大小/行数限制、分页和元数据过滤、关闭/未知工作区 404 |
| 知识事务与隔离 | 并发仅一方更新、写后异常回滚、提交确认丢失后读取核对、跨 Worker/资源实例可读、根路径/工作区隔离 |
| 知识状态与生命周期 | 删除后历史消息保留而新读取不可见、不回写；原生嵌套子图继承 Store 仍不能写入或越界；命名空间绑定不可替换、子命名空间不可读；批处理任务退出 |
| MCP 授权与契约 | 固定凭据、独立 Session、默认 Profile 不扩权、名称/说明/Schema/annotations 漂移、别名冲突、目录预算、外部 $ref 拒绝、无关工具变化不改变绑定 |
| MCP 执行边界 | Hook 最终参数校验、混合批次只读继续而写拒绝、Hook 修改共享消息或读转写不能绕过、重复调用 ID 不重放 |
| 输出与能力 | structuredContent 可见、图片/音频不进入 checkpoint、大型文本/artifact 有界、流式 JSON 在缓冲前限量、重定向不转发凭据、交互续发/扩展禁用、已知凭据脱敏 |
| 外部结果 | 只读业务错误可恢复、写业务错误终止；已写成功后响应丢失/不可解析/超大消息/超时均 unknown；确认成功后后续模型失败仍保留成功 |
| 中断与恢复 | 写请求发出后取消、失租、总超时、Worker 停止、真实子进程 SIGKILL；未知归档且远端效果只发生一次，无模型/工具恢复 |
| 数据库确认 | 派发、结果、最终发布提交确认丢失，只重试数据库，不重发 MCP RPC |
| 统一清理 | MCP-only 不创建资源、不引用服务不连接；数据库核对失败仍关闭连接；真实 Docker 工作区与 MCP 共存，容器移除后才完成发布 |
| 迁移 | 空库、旧核心基线、core_0002/core_0003 升级结构一致、重复初始化安全、各 Store 初始化中断点及无效并发索引修复、未知结构/版本拒绝、运行角色无迁移权限 |

真实邮箱、飞书账号接入、业务目的地限制和实际任务效果评估留给后续，不作为本阶段通过条件。
