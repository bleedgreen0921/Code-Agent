# 项目知识与外部工具

当前使用 LangChain 1.4.2、LangGraph 1.2.12、Checkpoint Postgres 3.1.2、原生 `langchain.mcp.MCPAdapter`、FastMCP slim client 4.0.1、MCP SDK 2.3.0。FastAPI/Starlette 为 0.143.1/1.8.0，JSON Schema 校验使用 jsonschema 4.26.0；阶段六还引入 fastmcp-tasks 4.0.1。完整安装以 requirements.lock 为准；不安装 FastMCP server extras 或独立适配包。本文说明项目知识和同步 MCP 路径，后台 MCP Tasks 的连接与恢复契约见 [持久任务与后台操作](持久任务与后台操作.md)。

## 部署和数据库

停止 API/Worker → 备份 → 安装锁文件 → `python -m db.migrate` → `python -m db.bootstrap` → `python -m db.doctor --json` → 同步重启 API/Worker。需要重新构建工作区执行镜像并更新固定 image ID。不要混跑旧新 Worker；配置变化的排队任务按 CONFIGURATION_CHANGED 结束，默认 chat 提交绑定继续兼容。

当前部署须迁移到 `core_0005`。阶段五的 `core_0004` 增加 `external_operations` 应用表，阶段六的 `core_0005` 增加 Task、依赖、后台操作和事件表，并扩展 Run 的关联字段。原生 Store 的 `store`、`store_migrations` 由迁移 owner 在同一迁移锁下调用 `PostgresStore(index=None).setup()` 初始化，不创建 pgvector、向量表或第二套知识表。并发索引在事务外创建；已知初始化步骤中断可重复执行，未知结构/版本在 DDL 前拒绝。API/Worker 不执行 DDL。运行角色可对数据表执行 DML，对 schema_version、alembic_version、checkpoint_migrations、store_migrations 只有 SELECT 权限。

readiness 校验应用版本、Store 结构、迁移版本、索引有效性和运行角色权限。Store 生命周期先收敛原生批处理任务，再关闭数据库池；不启动 TTL 清理。Checkpoint Postgres 3.1.2 的批处理关闭和 FastMCP 4.0.1 的交互/扩展控制有集中的版本兼容代码，升级框架时应连同测试复核。

## 项目知识配置与 API

在运行 TOML 增加：

```toml
[knowledge]
enabled = true

[[profiles]]
id = "project-knowledge"
tools = ["knowledge_get", "knowledge_search"]
```

默认关闭。开启后 workspace_read/workspace_write 增加只读知识工具，chat 仍为空工具，自定义 Profile 显式选择。知识 Profile 必须绑定已注册工作区，单独使用知识工具不需要 Docker。命名空间由工作区 ID 和规范根路径的 workspace_identity 派生；更改根路径或将 ID 用于不同根目录不会读取旧知识。模型不能提供命名空间，生产图和隐式继承资源的子图只能获得限定工作区的只读 BaseStore 视图。受控委派工具白名单仍不包含知识或 MCP 工具。可信工厂的标准 BaseStore 扩展接口保留。

所有管理 API 沿用 loopback、Host、Origin 限制和统一错误结构。管理请求本身是人工提交边界；聊天确认或 `confirmed=true` 不构成写权限。

| 方法 | 路径 | 参数 / 返回 |
| --- | --- | --- |
| GET | `/v1/workspaces/{id}/knowledge` | category/source 字符串等值过滤；limit 1–100，默认 30；offset 默认 0，最大 100000；返回 items 与 next_offset |
| GET | `/v1/workspaces/{id}/knowledge/{key}` | 完整条目及 ETag |
| PUT | 同上 | 完整 body；创建 `If-None-Match: *`，返回 201；更新 `If-Match: "VERSION"`，返回 200 和新 ETag |
| DELETE | 同上 | `If-Match: "VERSION"`，返回 204 |

键为 1–200 个 ASCII 字母、数字、下划线、点或连字符。PUT JSON 字段：title（1–200 字符）、body（UTF-8 最多 8192 字节、180 行）、category（1–100 字符）、source（1–300 字符）。版本由服务端生成，客户端不可指定；条目还包含 key 和 version。列表返回简短 summary，不返回正文。缺少前置条件为 428，版本冲突为 412；功能关闭或工作区不存在为 404。更新在同一事务中按命名空间和键加事务锁，用绑定当前连接的原生 abatch 读取、检查和变更，不进入后台写队列。取消/异常回滚；提交确认丢失时先 GET 核对当前条目，不自行重放。

```bash
curl -X PUT http://127.0.0.1:8002/v1/workspaces/project/knowledge/test-entry \
  -H 'Content-Type: application/json' -H 'If-None-Match: *' \
  -d '{"title":"测试入口","body":"使用 python -m scripts.postgres_integration 验证。","category":"testing","source":"maintainer"}'
curl -i http://127.0.0.1:8002/v1/workspaces/project/knowledge/test-entry
# 更新/删除时原样发送最近读取的 ETag，包括双引号。
```

Agent 的 `knowledge_get(key)` 返回当前正文、版本和来源；`knowledge_search(category?, source?, limit?, offset?)` 只按元数据等值过滤，不接受 query。没有 Embedding、关键词或语义检索，没有正文缓存、全量预加载、自动记忆提取或模型写入。内容变化不改变提交绑定；策略和实现版本进入绑定及运行快照。删除后新读取不可见，历史 checkpoint、工具消息及摘要仍是过去的快照，不回写 Store。

## MCP 配置、目录与凭据

仅接受服务端静态声明的 HTTP transport，不接受 stdio、脚本、任意 MCP 配置对象或 HTTP/模型提供的地址和凭据。默认 HTTPS；loopback HTTP 必须显式 `allow_insecure_loopback = true`。地址不得包含 userinfo、query 或 fragment。保留 TLS 校验，禁止重定向和自动 OAuth 登录，不使用环境代理。OAuth/业务 API 由对应 MCP 服务实现。

先建立绝对路径目录文件，初次导出可包含 `{"tools":[]}`。首次声明服务时 `tools = []`，导出成功并人工审阅后再选择工具：

```toml
[mcp]
init_timeout = 10.0
call_timeout = 30.0
cleanup_timeout = 10.0

[[mcp.servers]]
id = "business"
transport = "http"
url = "https://mcp.example.com/mcp"
account_id = "team-account"
catalog = "/srv/agent/catalog/business.json"
bearer_env = "BUSINESS_MCP_TOKEN"
# 或 headers_env = { X-Api-Key = "BUSINESS_MCP_API_KEY" }
tools = [
  { name = "lookup", alias = "business_lookup", access = "read" },
  { name = "create", alias = "business_create", access = "write" },
]

[[profiles]]
id = "business-agent"
tools = ["business_lookup", "business_create"]
```

使用与服务端一致的 AGENT_RUNTIME_CONFIG：

```bash
# 仅 Worker 和显式目录导出命令需要实际凭据。API 不解析环境变量值。
export BUSINESS_MCP_TOKEN='set-through-your-secret-manager'
python -m scripts.mcp_catalog export business --output /srv/agent/catalog/business.new.json
python -m scripts.mcp_catalog validate /srv/agent/catalog/business.new.json
# 人工审查名称、说明、输入/输出 Schema、annotations；替换目录后同步重启。
```

导出使用排他创建，不覆盖现有文件；导出并不启用工具。目录为标准 tools/list JSON，文件最多 1 MiB，输入/输出 Schema 只允许本地 $ref，不允许外部 Schema 资源标识。别名全局唯一，不能与内置/可信工具冲突。单 Profile 所选完整工具契约最多 32 KiB。服务新增加的其他工具不自动开放；远端 readOnlyHint 不是授权依据。读写分类由管理员明确声明，Profile.tools 再次白名单授权。业务参数限制继续通过可信 Python validators 扩展，不预设邮箱收件人或飞书目标规则。

API 启动只读本地目录，不连接服务。同步 MCP 工具默认使用 `execution="sync"`；Worker 为本次 Run 所引用的同步服务分别创建独立客户端和原生 MCPAdapter，在模型调用前握手、重新发现并核对所选完整契约；缺失/变化按 CONFIGURATION_CHANGED 失败。仅将绑定实际连接的工具实例交给权限层；最终参数在 Hook 之后按冻结 JSON Schema 校验，再执行可信业务校验。无效参数以原调用 ID 的错误消息反馈，不发送 RPC。后台工具使用 `execution="background"`，由 Task 路径组装和监控，不使用同步 MCPAdapter 连接。

MCP 写调用必须独占模型的一次工具批次，混合/多个写调用拒绝写入，普通工具照常执行。批次在并行工具 Hook 运行前冻结；最终入口再次核对原批次和 ID。知识、MCP、委派继续共用已有工具额度，不增加 Worker 槽位。

初始化总期限最多 10 秒，调用最多 30 秒，均受 Run 剩余期限约束；本地清理最多 10 秒。协议 JSON/SSE 消息在解析前限制 1 MiB；模型可见结果和 artifact 各自受输出配置约束，最高 16 KiB/200 行。纯 structuredContent 转为可见 JSON 文本；图片、音频、二进制和资源链接只保留类型说明，不保留 base64，不下载链接或执行返回内容。配置的凭据仅解析到本次连接，已知凭据反射到结果时会脱敏。

同步客户端关闭响应缓存及可选扩展，不提供 sampling、宿主 roots 或审批恢复；elicitation 明确 decline，要求重发 tools/call 的 input-required 结果直接失败。后台 MCP 连接独立启用原生 Tasks 扩展，仍不支持 input_required 交互。使用标准 initialize 会话协商，不自动重发工具请求；协议 SSE 读取恢复只允许 GET，不重新执行工具。工作区容器始终无网络，Profile 授权的外部工具通过 Worker 连接；运行上下文分别说明这两项边界。

## 同步外部写入核对与故障

发送写 RPC 前，必须在有效租约下提交并确认 external_operations 派发记录。记录关联 Run、租约、原调用 ID、服务/逻辑账号/工具、最终参数哈希、派发 ID、时间、状态、脱敏错误码和有界回执；不存原始参数或凭据。同一 Run/调用 ID 不再次派发。提交确认丢失只查询/重试数据库操作，不重发 RPC。

| 事件 | Run 与记录行为 |
| --- | --- |
| 只读业务错误 | 错误 ToolMessage，模型可修正参数 |
| 连接/协议异常 | Run 失败，不自动重试 |
| 写操作明确返回错误 | 记录 error，MCP_WRITE_ERROR 终止 Run；不假定没有部分副作用 |
| 写发出后超时、断线、结果不可解析 | 记录 unknown，MCP_RESULT_UNKNOWN 终止 Run |
| 写成功后后续模型失败/取消 | 保留 succeeded，不回滚或重发 |
| 取消、失租、Worker 停止 | 保留原 Run 终态；未确认写入另记 unknown |
| Worker 被强制终止 | 下次维护将失效 Run 的未确认派发归为 unknown，不恢复执行 |
| 本地连接/容器清理失败 | 不发布 completed；继续现有租约和资源诊断流程 |

所有退出路径先冻结新调用、等待本地工作退出、关闭 MCP 连接，再清理工作区容器和发布结果；清理期间继续续租。数据库核对失败也会尝试关闭连接。仅使用 MCP 的 Run 不创建 Docker 执行资源；未引用 MCP 的任务不要求服务可达。

通过 `/v1/runs/{id}/trace`、`/timeline`、`python -m db.trace_run RUN_UUID` 或 `python -m db.doctor --json` 查看 external_operations。结果未知时，依据服务、账号、工具、时间、参数哈希和已有回执，人工到外部服务核对。不要将 unknown 当作成功，不要为核对自动提交新 Run 重试写入。同步写入审计不保证跨 Run 的业务恰好一次，不证明远端取消成功，也不提供审批、恢复、强制重试、后台对账或结果修改接口。后台 MCP Tasks 另由 background_operations 持久化和监控，通过 Task operations API 查询与取消；这不会恢复或重发未知的同步写入。Run 结果仍只有 answer。

## 验证

统一入口仍为 `python -m scripts.postgres_integration`。真实 PostgreSQL、Docker 和合成模型；MCP 使用官方 SDK 服务与进程内受控 HTTP transport。HTTP/network 禁令保持启用。知识与同步 MCP 的阶段五验收覆盖知识 API/版本冲突/事务、根路径隔离、子图资源继承、历史删除、Store 任务关闭、静态目录、实例权限、Hook 最终参数/原批次、输出边界、写结果未知、取消/失租/SIGKILL、数据库确认丢失及发布前清理。阶段六进一步覆盖 Task、后台操作和原生 MCP Tasks，见 [阶段六验收](阶段六实施验收.md)。真实邮箱、飞书接入和业务规则不属于上述验收范围。
