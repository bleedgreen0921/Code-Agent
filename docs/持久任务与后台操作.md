# 持久 Task 与后台操作

Task 独立于 Conversation。调用方通过 API 设置目标、Profile、工作区和最多八个已存在的前置 Task；Agent 无创建 Task 或修改依赖的工具。依赖不可修改，因此 API 无法形成环。

## 部署和配置

使用 Python 3.12，安装 `requirements.lock`。升级前停止旧 API/Worker，以迁移 owner 执行 `python -m db.migrate`，再执行 `python -m db.bootstrap`。`core_0005` 增加 tasks、task_dependencies、background_operations、task_events，Run 增加 task_id、execution_no。既有会话、知识、checkpoint 和同步 MCP 审计保留。运行角色只有数据表 DML，无 DDL 或迁移版本写权限。

执行 `python -m scripts.build_execution_image`，将新镜像的不可变 ID 配置到 runtime.toml；同步启动 API/Worker。镜像包含后台监督入口。仅在 Profile 中显式选择后台工具；配置示例包含 `task-workspace`。三个原有内置 Profile 的工具列表保持不变。

环境变量均以 `AGENT_` 开头：

| 后缀 | 默认 | 含义 |
|---|---:|---|
| MAX_UNFINISHED_TASKS | 32 | 未完成 Task 数量 |
| TASK_TIMEOUT | 3600 | 总期限（秒），包含依赖、排队、操作等待 |
| BACKGROUND_TIMEOUT | 1800 | 操作期限（秒），不超过 Task 剩余期限 |
| MAX_ACTIVE_OPERATIONS | 2 | 全局活动或未清理操作数 |
| MAX_TASK_ACTIVE_OPERATIONS | 1 | 每 Task 活动或未清理操作数 |
| MAX_TASK_OPERATIONS | 4 | 每 Task 累计操作启动数 |
| BACKGROUND_POLL_SECONDS | 1 | 本地轮询间隔，远程尊重更大的服务端间隔 |
| RECONCILIATION_SECONDS | 30 | 操作监控租约及取消核对窗口 |

原有 Run 活动/排队/未完成上限仍为 2/8/10；普通 Shell 仍有 30 秒期限。每 Task 最多五次 Run，不自动重试普通失败、命令或远程提交。

## API

所有接口沿用本机限制、严格请求模型和错误封装。列表使用 `limit`、`cursor`，Task 列表还接受 `status`。所有 ID 均为 UUID。

```sh
curl -sS http://127.0.0.1:8002/v1/tasks \
  -H 'Content-Type: application/json' -H 'Idempotency-Key: build-001' \
  -d '{"task":"执行获准的构建并报告结果","profile":"task-workspace","workspace_id":"project","depends_on":[]}'
```

`POST /v1/tasks` 首次返回 202，幂等重放返回 200。完整输入参与比较，依赖顺序不影响等价性；重复依赖为 422，未知依赖为 404，创建时依赖已失败或取消为 409。创建后依赖失败传播 `DEPENDENCY_FAILED`。Task 期限由服务端决定；不提供修改、重跑或人工确认结果接口。

| 路径（相对于 /v1） | 方法 | 用途 |
|---|---|---|
| /tasks | GET / POST | 分页查询 / 创建 |
| /tasks/{id} | GET | 目标、依赖、状态、当前 Run、答案 |
| /tasks/{id}/cancel | POST | 取消整个 Task |
| /tasks/{id}/timeline | GET | Task 和操作状态事件 |
| /tasks/{id}/operations | GET | 操作列表（最多四条） |
| /tasks/{id}/operations/{operation_id} | GET | 元数据与持久化有界结果 |
| /tasks/{id}/operations/{operation_id}/cancel | POST | 仅取消这个操作 |

`GET /v1/runs?task_id={id}` 查询执行历史。Run 详情和 trace 包含 task_id、execution_no。取消 Task 所属 Run 会取消整个 Task。单操作取消是可供 Agent 处理的结果；不会撤回已发生的文件或外部更改。

## 状态和结果衔接

Task 为 waiting_dependencies、queued、running、waiting_background、cancelling、completed、failed、cancelled。等待依赖或 Run 容量时不创建 Run、不占 Run 队列；Run 创建后才计算 60 秒排队期限。

后台操作为 starting、running、cancelling、succeeded、failed、cancelled、unknown。`cleanup_state` 独立表示 pending、released、failed。结果已知不代表资源已清理；未确认释放仍占容量及本地工作区。Task 只有在全部结果交付成功 Run、全部操作结束且清理确认后完成。Run 成功时可以只是阶段报告；waiting_background 的 Task.answer 仍为空。

Agent 通过 `start_background_shell(command,cwd=".")` 立即启动独立容器；该启动必须独占工具批次。命令不继承普通 Shell 的 cwd、变量或进程。`background_status` 不等待结果；`background_result` 读取已保存结果；`cancel_background` 只请求取消当前 Task 的操作。这些工具只允许 Task 根 Agent 执行，子 Agent 没有启动或取消能力。

后台期间当前根 Agent 可继续读取、搜索和只读委派；文件可能正在变化，多次读取没有一致快照保证。普通 Shell、文件编辑和新的本地后台启动被拒绝。其他 Run/Task 不能进入相同或重叠父子目录。操作结束并确认容器删除后才能解除保护。

每次 Run 使用独立 thread_id。续 Run 只继承上一成功 Run 已发布最终 checkpoint 的消息，重新注入 Task 约束、依赖数据及未消费结果；不继承 Todo、配额、容器、Shell 环境或句柄。结果和摘要都是数据，不能增加授权。命令非零退出、远程失败和单操作取消可以交给 Agent 修复；未知结果、异常 Run、资源故障会终结 Task。

## 原生 MCP Tasks

工具选择支持 `execution="sync"`（默认）或 `"background"`。模式参与绑定指纹与 trace。后台连接独立启用官方 Tasks 扩展，核验现代协议、服务能力及冻结工具契约。使用 `fastmcp_tasks.call_tool_task` 返回句柄；监控通过 `ToolTask.status()` 与 `cancel()`，不调用隐藏等待的 `result()` 或 `wait()`。

接入服务必须支持在连接关闭后，用同一服务、账号及凭据重新连接查询和取消原句柄。项目不运行 FastMCP 服务端调度器或 Redis。协议不支持时直接报告，不退回同步调用；同步返回的已知完整结果会保存为协议异常结果，不会再次提交。input_required 会被请求取消并报告不支持，不继续交互。

取消请求接受后继续查终态；服务端可能已完成，远程副作用无法保证撤回。句柄不向 Agent 暴露，Agent 只能使用项目 operation UUID，不能访问别的 Task 或账号。实际凭据摘要、服务配置和协议身份变化时拒绝用旧句柄访问新身份。

## 故障核对

`python -m db.doctor --json`、Task timeline/operations、Run trace 提供持久化证据。操作在外部动作前先写派发记录，原始工具调用 ID 去重。确认丢失只重试数据库确认或查询已有资源，不重发 create/start/远程提交。

Worker 重启可接管独立操作租约，按稳定容器名称/标签或已保存远程句柄查询。已执行 Run 因重启失租失败时，其 Task 失败并取消资源，不恢复失败 checkpoint。waiting_background Task 的操作继续核对；已知结果准备好后原子创建唯一续 Run。

unknown 表示无法核实执行情况，Task 失败并保留诊断与未释放占用；迟到结果不会恢复 Task。配置/daemon/所有权不匹配时不得手工将记录改为 released。先核对原 Docker daemon 的标签、容器和停止状态，或原账号的远程句柄及实际外部结果。清理扫描可以继续查询已知资源，不会调用模型或重放提交。

本地日志使用 Docker local 驱动，限制为 64 KiB、一个文件。监督入口持续排空命令输出，仅保留最多 16 KiB/200 行，并记录退出码、超时和截断标记；期限到达会终止整个容器。Run 容器与后台容器分别清理。远程取消为协作请求，失联服务可能仍在执行，数据库容量约束不能停止它。
