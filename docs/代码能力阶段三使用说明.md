# 代码能力阶段三：项目修复闭环

项目入口为 `examples/python-repair/README.md`。先复制到独立路径并初始化 Git，
再按阶段二方式注册该路径，加载 `config/runtime.code.example.toml`，选择 code-fix。
不可把框架仓库内的示例原件注册为演示工作区。

示例明确允许修改 sample.py 和相关开发测试；标准库检查在 /workspace 内离线运行。
先做边界缺陷修复任务，再做负数参数的回归任务；每个 Run 均保持 16 次模型、10 次工具上限。
开发期真实失败是继续修正的依据。新增回归应先失败后通过；命令缺失、未执行和断言失败分别报告。
失败或取消不会回滚文件，也不会自动重放 Run。最终回答包含修复摘要、修改内容、检查结果、遗留问题，
说明用户已有暂存、未暂存及未跟踪内容的保留情况。普通 code-fix 不生成正式验证报告。

验收：`python -m scripts.postgres_integration`。使用 SyntheticModel 驱动真实 Docker、Git、Worker、
PostgreSQL；禁止真实模型和外部 HTTP。`tests/test_python_repair.py` 保留部分修正后再次失败与新增回归先红后绿两条场景。
