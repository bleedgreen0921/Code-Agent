# 第三批：可信验证与重复错误控制验收

实施日期：2026-10-16。以 core_0007、413 项既有验收为基线，Git 基线为 `a4209c17b22c17e20d77740973d5aadd0151efe6`。对应[总计划](异常处理与执行一致性增强计划.md)，行为与部署契约见[第三批说明](第三批可信验证与重复错误控制.md)。代码保存在工作区，未提交。

## 交付范围

1. 可信 Extension 的严格异步验证注册、report/required 模式、有限正超时及默认关闭的 no_progress_enabled。启用策略写入冻结绑定、Profile 指纹和运行快照；未启用保持旧绑定公式。
2. 严格且冻结的 VerificationResult、VerificationReport、checkpoint 引用和最小验证上下文。报告仅保存控制器来源、哈希、时间、真实文件观察与有界说明，不保存文件正文或异常原文。
3. core_0008 仅新增可空 runs.verification，对象及 32 KiB 数据库约束；保留全部历史结构签名，历史报告保持 NULL，运行角色不增加 DDL。
4. 原生最终 checkpoint 后、清理前的受监督验证，独立的 Profile 只读文件入口、范围与哈希记录、结束复核、文件/访问/序列化预算，以及控制异常和总期限优先级。
5. 原事务内报告绑定、清理/取消/租约/Task 门禁和原子发布；提交回执或首次确认读取丢失后仅确认同一冻结结果。required 阶段 Run 不成为消息来源、不提前消费可信后台结果，原队列继续收敛并保留最多五次 Run。
6. 原生重复错误 middleware，仅统计可信参数/权限/固定文件边界的三类错误，按模型声明顺序处理并发批次，摘要和下一次模型前停止三次连续重复。根与子计数隔离，子失败返回诊断并允许父继续，其他控制异常不降级。
7. Run 查询/trace 与 Task 当前 Run 报告投影、安全日志、注册示例、运维与兼容说明。

没有新增真实测试/Lint/构建验证业务、验证重试、修复循环、额外生成、自动重放、任务恢复、工作区回滚、报告覆盖接口或依赖升级。
