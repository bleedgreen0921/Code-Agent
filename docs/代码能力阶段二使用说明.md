# Git Review 阶段二使用说明

本阶段扩展[渐进总计划](代码分析Review与修复能力渐进实施计划.md)中的阶段二，沿用现有 `/v1/runs`、Profile、原生工具循环和 ToolMessage。数据库仍为 `core_0008`，不增加接口或正式验证器。基础指定代码审查仍支持非 Git 工作区。

## 部署

使用独立的 `config/runtime.code.example.toml`，替换工作区、Skill 目录和不可变镜像三个占位符。运行 `python -m scripts.build_execution_image` 重建 `agent-execution:workspace-v2`，把输出的不可变镜像 ID 同步配置给 API 和 Worker，按既有流程检查并重启。旧 `workspace-v1` 镜像不能接收新工具。不需要数据库升级，不改变依赖版本。配置、工具 schema、Skill 或执行版本变化时，既有不兼容绑定按原规则拒绝，不自动重放任务。

注册的工作区根必须就是仓库根，且有完整内部 `.git` 目录。不会自动寻找或挂载上级仓库；外置元数据 worktree、子模块工作区、裸仓库、alternate 对象存储及 partial clone 暂不支持。不自动 fetch 或修复缺失对象。

| Profile | Git 工具 | 权限 |
|---|---|---|
| code-analyze | 无新增 | 原有只读工具 |
| code-review | git_status、git_log、git_diff、git_read_file | 只读工作区挂载，无编辑和 Shell |
| code-fix | git_status、git_diff | 保留既有编辑和 Shell |

内置 Profile 及子 Agent 白名单不变。只选择 Git 工具的自定义 Profile 也必须绑定工作区，并走相同资源预留、授权、调用预算、期限、日志及清理流程。Skill 是使用方法，不是 Shell 权限防火墙。

## 四个工具

参数严格校验，禁止额外字段。没有任意命令、Git 参数或自选工作目录入口。路径是字面工作区相对路径，不接受绝对路径、`..`、NUL 或 `:(...)` pathspec 魔法；空格、中文、制表符、换行、通配符字符和前导 `-` 均作为文件名处理。文件名和文本行经 JSON 转义显示。

| 工具 | 参数与默认值 | 返回内容 |
|---|---|---|
| git_status | offset=0；limit=50，范围 1–100 | HEAD、分支；逐文件 staged、unstaged、untracked、conflict；展开未跟踪目录 |
| git_log | revision="HEAD"；offset=0；limit=10，范围 1–50 | 完整提交 ID、父提交 ID、作者、作者时间和标题；不返回正文 |
| git_diff | source=staged/unstaged/commit；commit?；view=files/patch，默认 files；path?；start_line=1；max_lines=200 | 先列变更文件与对象/模式，再按文件读 patch |
| git_read_file | source=commit/index；path；commit?；start_line=1；max_lines=200 | 原文件行号、blob ID、SHA-256、来源版本及 UTF-8 普通文件正文 |

`offset` 非负；`start_line` 从 1 开始；`max_lines` 范围 1–200。`commit` 仅允许且必须在 `source=commit` 时提供。patch 必须提供一个文件路径。引用接受单个本地提交引用及 `^1`、`~2` 等祖先表达式，不接受范围、选项、tree/blob、歧义或无效引用。解析后固定完整提交 ID；`git_log` 后续分页必须使用首次返回的完整 `revision`，不能继续用会移动的 HEAD。

比较规则：`staged` 为 HEAD → index，没有首个提交时将暂存文件作为新增；`unstaged` 为 index → 工作区；`commit` 为第一父 → 目标提交，根提交由 Git 原生根比较处理。合并提交返回父数量，并明确注明第一父比较。暂存上下文只读 stage 0，冲突索引没有唯一暂存版本时明确报错。

## 分页和覆盖范围

模型可见正文和 artifact 同时包含来源、版本、比较基准及截断状态。状态/历史使用 `next_offset`；文件清单/patch/文件正文使用 `next_line`。续读位置按实际完整输出的记录/行计算；字节或行预算先耗尽时不按请求上限跳项。空结果与读取失败明确区分。

`git_diff` 的行位置是工具输出位置，不能当作源码行号；定位问题使用 hunk 中的新旧行号。`git_read_file` 显示原文件行号。只返回下一页起点，不保证昂贵的完整总数。超长单行或单条记录无法放入预算时不跳过该条，会说明未读取并保留起点；增加预算或披露无法覆盖。二进制、非 UTF-8、超出已有文件大小上限的 blob、symlink、目录和子模块内部内容均不伪装为完整文本。子模块最多展示指针元数据。

暂存区和工作区为实时观察，多次调用不是原子快照；检测到版本变化时重新观察并说明变化。历史内容不依赖当前工作区同名文件、文件是否存在或 HEAD 是否移动。删除文件或修改前上下文可以读取已经确定的第一父提交，必须明确标为旧版本。

Git 子进程在容器内用固定 argv 和非交互环境执行，关闭可选写锁、fsmonitor、pager、颜色、外部 diff 和 textconv，不递归读取子模块。即使工作区可写也不写索引、引用、对象、配置或工作文件。当前状态和未暂存差异对配置了外部 clean/process filter 的仓库采取保守拒绝，无论该过滤器是否实际用于所选文件；暂存和历史读取使用原始对象，不运行 filter 或 LFS。Git 的可选锁与外部过滤器机制见 [Git 环境变量](https://git-scm.com/docs/git#Documentation/git.txt-codeGITOPTIONALLOCKScode)及 [Git 属性过滤器](https://git-scm.com/docs/gitattributes#_filter)。

stdout/stderr 流式有界读取，分页提前结束即终止并回收子进程；真实超时、取消、失租和环境丢失继续走既有控制异常及容器清理，不自动重试失败命令。错误诊断使用既有 failure_info，日志不保留源码、提交正文或完整参数。

## 两种 API 自然语言示例

当前未提交改动：

```json
{"task":"审查当前未提交改动。先查看状态，分别审查暂存、未暂存差异和未跟踪文件；暂存上下文读取 index。同一文件的两个版本分别标明。列出未覆盖内容，不修改文件。","profile":"code-review","workspace_id":"project"}
```

历史选择与指定提交：先提交以下请求取得候选，在现有会话的后续任务中给出选定 ID；不增加选择接口或等待状态。

```json
{"task":"列出最近 10 次本地提交的完整 ID、父提交、作者时间和标题供我选择，暂不进行审查。","profile":"code-review","workspace_id":"project"}
```

```json
{"task":"审查提交 <完整提交ID> 相对第一父提交的变化。相关上下文从该提交读取，删除文件从已确定的第一父读取并标为旧版本。合并提交注明第一父比较。列出覆盖及遗漏范围。","profile":"code-review","workspace_id":"project"}
```

如果目标不明确且有多个候选，列出候选或澄清范围，不能声称完成指定提交审查。最终保留“审查结论／问题清单／审查范围与未确认事项”三个 Markdown 二级章节，在范围中说明模式、目标版本、比较基准和实际覆盖；冲突、不支持内容、截断和预算不足均须披露。

修复任务在仓库可用时核对修改前后状态和两类差异，继续保护用户已有修改，不自动暂存、提交、回滚或清理。所有结果区分静态审查、实际执行检查及可信最终验证；这些 Profile 仍未接入正式验证器，`verification` 语义不变。
