# 第二批：后台核对与清理可靠性

对应[总计划](异常处理与执行一致性增强计划.md)，以前一批 core_0006 和 310 项验收为基线；验收证据见[第二批验收](第二批后台核对与清理可靠性验收.md)。本批不增加模型、Shell、文件修改、业务 MCP 调用或后台启动的恢复。

## 配置与冻结

服务端 runtime.toml 的 `[reliability]` 为严格配置：观察最大连续失败 5 次、窗口 30 秒、退避基数 1 秒/上限 8 秒；未知后的清理观察基数 8 秒/上限 60 秒；发布预留 2 秒；安全取消上限 3 次；维护最大失败 5 次/30 秒、退避 1 秒/8 秒。时间有限且为正，次数是严格整数，上限不得低于基数；取消上限不得超过 3。

`cancel_retry_safe` 位于每个 `[[mcp.servers.tools]]` 选择项，默认 false，只有后台工具可以开启。服务器清单、Profile 绑定、操作的冻结绑定与运行快照保存相关授权；未选工具的授权不影响该 Profile。false 不改变原有同步 MCP 工具清单。新的期限策略进入所有 Profile 指纹，历史绑定不重写；与新版本不兼容的排队执行按 CONFIGURATION_CHANGED 安全拒绝。

## 观察轮次与未知事实

一次观察轮次覆盖判断原资源状态所需的 daemon/inspect/logs，或原生 MCP Tasks 连接、契约与原句柄状态。只对白名单中的连接中断、连接失败、读取超时恢复；普通业务读、执行中的 healthy 和初始化失败不获得恢复能力。异常组的全部叶子均须满足白名单；SDK 连接包装需有可信的瞬时原因，取消时 SDK 折叠的连接关闭还须有本连接的传输故障标记。权限、凭据、绑定、身份、协议、非法结果与程序错误立即停止本轮。

监控先核对 token、租约和冻结配置，在事务中记录开始，在事务外观察，再在事务中确认完成、计数和 next_poll_at。数据库确认方法独占写入重试，不重做远程观察。提交确认丢失按同一观察起点确认完整提交；新 Worker 接管 inflight 轮次只扣一次未确认失败。

第一次失败计为 1，第一次确认失败建立窗口，后续失败不延长窗口。完整观察成功才清零连续失败、窗口起点与最后错误，并更新 last_observed_at；仅连接成功不算。预算内保留执行主状态、主错误和清理状态，Task 不因单次瞬时观察失败而失败。

第 n 次失败后的本地间隔为 `min(cap, base * 2^(n-1) * uniform(0.8, 1.2))`。正常恢复使用 1/8 秒，未知后使用 8/60 秒；还受既有轮询下限和服务端间隔约束。服务端间隔以毫秒向上取整并持久化；非有限、负数和本地不能安全表示的值按协议错误处理。创建回执与首次轮询下限原子保存。后台轮询下限与监控租约长度也随操作冻结。next_poll_at 是唯一调度唤醒字段，执行期限、失败窗口或取消核对窗口可以先唤醒处理到期，不能因此提前发送状态查询。

达到次数上限或窗口到期，未终结执行以 BACKGROUND_OBSERVATION_EXHAUSTED 进入 unknown，并在同一事务中使 Task 失败；原身份、已有结果和资源占用继续保留。已确认执行终态受到保护，预算耗尽只标记清理未确认。unknown 后低频观察仅补记原资源的迟到终态和清理事实，不恢复 Task、不消费结果、不创建续 Run、不调用模型或重新派发。没有可靠 MCP 句柄时不反复建连查询。

每个观察调用受监控租约、既有失败窗口、单次调用上限与保存/断连余量共同限制；事务或锁中不等待退避。Docker stop/rm 前重查原 daemon、容器标签、ID 和监控授权。清理响应丢失后，下一轮先观察原资源的实际状态；新的可信观察仍显示需要清理才执行原动作。清理失败不覆盖执行主错误。

## 取消事实

取消意图、尝试与服务端确认分别持久化。先查询原句柄；已终态直接保存权威结果。仍活动时先保存意图，再以唯一 ID 预留尝试，之后只调用一次 handle.cancel；合法返回后关联尝试保存 cancel_acknowledged_at。确认表示请求被接受，不能证明终态、清理完成或副作用撤销。

默认最多一次尝试；预留后崩溃即占用次数，发送前崩溃和确认丢失均不推断未发送。只有原操作冻结清单明确授权 cancel_retry_safe=true，且前次记录为允许的瞬时传输失败时，才允许新的尝试，累计至多 3 次。每次仍须先查状态，遵守退避和远程间隔。成功确认后不重复取消；首次尝试启动的既有取消核对窗口不因重试或 Worker 更换而延长。非法响应和身份/协议问题不增加尝试。取消与完成竞争保留权威完成结果。

历史 cancel_sent_at 只表示首次已记录尝试；迁移保守占用一次、保留接收未确认，不生成确认时间或追授安全重试权限。

## 执行、清理与维护

Run 数据库绝对 deadline_at 不变。Worker 在准备与 graph 前设置 effective_deadline_at：绝对期限减去该 Run 实际启用的 Docker 清理上限、MCP 清理上限及发布预留。两类资源清理上限相加；子 Agent 继承同一期限，不重复预留；独立后台执行由后台监控收敛。

准备、整个 graph、摘要、模型、子 Agent、工具和后台派发共享该期限。remaining_execution 是公共预算读取入口，后续验证器可以复用，本批未实现验证器。每次动作检查剩余时间，工具/MCP 调用上限取配置和剩余时间的较小值。剩余不足按 RUN_TIMEOUT 收敛。

graph 取消等待、MCP 断连、Docker 与本地进程收敛共享总清理截止时间。各 scope 仍受自己的清理上限约束；Docker 异常诊断与提交确认不能重新获取完整预算。一个资源失败不跳过其它资源的剩余清理。发布和提交确认共享一次发布预留并受绝对期限约束，不重跑 Agent 或工具；清理未确认、取消、失租或期限失效不能发布成功。

维护数据库阶段独占连接恢复：最多 5 次/30 秒，抖动 1/8 秒，维护成功清零。维护等待和数据库等待可被停止信号打断；维护故障期间停止 admission。认证、权限、结构/SQL 和程序错误不重试。预算耗尽设置停止信号，收敛本进程任务并非零退出，由已有管理器重启；最终 stopped 心跳有界。

续租返回已确认 lease_until。独立本地监督使用最后一次数据库确认的租约期限；数据库不可用不会把本地授权改成“当前时间 + 租约”。到期取消执行、关闭动作入口；数据库恢复后旧 token 仍不可续租或发布。

## 数据与只读接口

core_0007 只扩展 background_operations：观察计数/窗口/最后成功/有界错误/开始与 inflight、远程间隔和 not_before、取消尝试次数/ID/时间/确认与有界错误。计数非负，取消次数 0..3，两个新增诊断 JSONB 可空、必须是对象且至多 2 KiB；failure_info 复用版本 1。

operation 查询按 observation/cancellation 分组投影诊断；不暴露 monitor token、内部尝试 ID、凭据或完整绑定。Task/Run/doctor 的 unresolved 在同一只读快照中增加关联诊断，预算内故障不计入 unknown；已确认执行但未释放的资源仍单独计数。读取不触发观察、取消、清理或调度。安全日志白名单增加恢复次数、下一次观察、阶段和取消确认结果，保留固定事件及原有大小限制。

部署顺序：停止旧 API/Worker → owner 执行 `python -m db.migrate` → `python -m db.bootstrap` → 运行角色 `python -m db.doctor --json` → 同步启动新版本。readiness 拒绝旧版本或结构漂移；运行角色仍无 DDL 权限。迁移不重写历史绑定、结果、主错误、unknown 或资源占用。
