# 第一批：异常契约与诊断验收

实施日期：2026-10-16。对应 [总计划](异常处理与执行一致性增强计划.md)，契约与部署说明见 [第一批异常契约与诊断](第一批异常契约与诊断.md)。

## 交付范围

1. 统一严格 failure_info 与可信分类；保持原生 ToolMessage、Hook、参数错误及控制语义，增加 HOOK_CONTRACT_ERROR/PERSISTENCE_FAILED。
2. core_0006 只新增三个可空 JSONB 字段；完整保留历史结构签名、数据和 checkpoint，bootstrap/readiness 拒绝旧版本或漂移。
3. 固定镜像后台回执完整严格验证，Docker 原身份先于停止/删除校验，MCP 句柄和状态身份关联并使用 SDK 已解析的 is_error/outputSchema。
4. 普通操作更新保护终态、完整结果与身份；unknown 与 Task 失败原子提交；内部迟到事实补记不恢复 Task、不消费结果、不发布 checkpoint；清理不覆盖执行结果。
5. API/Worker 共享安全 JSON 日志，只记录白名单、固定事件及安全堆栈；详情/doctor 使用共享只读未决投影。

未增加模型/工具重试、观察退避、取消重试、恢复/覆盖接口、验证器、自动重放或工作区回滚。requirements.lock 与框架版本保持不变。保留实施前已有文档及 benchmarks 修改。

## 验收方式

统一完整入口为 `python -m scripts.postgres_integration --port 55436`。真实隔离 PostgreSQL 16、固定不可变 Docker 镜像、SyntheticModel、进程内真实 MCP SDK HTTP 服务。测试入口禁止真实模型和外部 HTTP/网络，JUnit 报告必须非空且失败、错误、跳过均为零。

最终报告、代码/依赖/镜像指纹、完整入口日志、迁移/bootstrap/doctor 与清理结果由统一入口保存。代码版本使用 Git 基线及逐文件 SHA-256，明确工作区未提交，避免将基线提交误认为本批已提交版本。
