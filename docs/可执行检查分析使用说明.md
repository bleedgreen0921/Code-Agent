# 可执行检查的隔离代码分析

新增入口执行：创建 Task → 固定源码与 Git 视图 → 只读分析 → 按需独立检查 →
结构化报告校验 → 清理 → 有效租约下正式发布。默认关闭。旧 Profile、旧 Run/Task
接口和 code-fix-checked 固定验证器不迁移到这个流程。

## 部署与可信注册

部署限定 API、Worker、Docker 同一 Linux 主机，并共享规范绝对存储路径。准备 Python
3.12、PostgreSQL 和执行镜像中的项目依赖。运行时禁止拉取镜像和安装依赖。

1. 停止旧 API/Worker，备份数据库。
2. 安装 requirements.lock，执行 `python -m db.migrate`、`python -m db.bootstrap`。
   新迁移是 core_0009；历史迁移和历史结构签名保持不变。
3. 在所有注册工作区外创建受管目录。执行用户为 Worker 的 UID:GID；root Worker
   必须明确配置非 root UID。存储不能位于工作区内，也不能包含任何注册工作区。
4. 执行 `python -m scripts.build_execution_image`，将最后输出的不可变 image ID 填入
   config/runtime.code.analysis.example.toml 的副本。替换工作区和受管目录占位路径。
5. 设置 `AGENT_RUNTIME_CONFIG` 和原有数据库环境变量。
6. 使用同一可信 Python 注册启动 API、Worker 和环境检查。示例：

```bash
python -m scripts.code_analysis_example --role doctor
python -m scripts.code_analysis_example --role api
# 另一个终端还需 AGENT_MODEL_URL、AGENT_MODEL，按需 AGENT_MODEL_KEY
python -m scripts.code_analysis_example --role worker
```

示例启动模块注册 project-unittest 和 project-pytest。部署方可复制该模块，在可信
Python 中构造 ProjectCheckDefinition 和 CheckAdapter，并通过
`Registry.from_env(project_checks=(...), check_adapters=(...))` 交给 Resources。
TOML 仅选择注册 ID、工作区授权检查集、默认检查集和预算；HTTP 不能传命令、argv、
镜像、宿主机路径或 Python 导入入口。普通 scripts.serve 没有该示例的检查注册，
不能与使用这些定义的 Worker 混用。无检查的静态分析可以直接使用普通启动入口。

定义包含 ID/版本、适配器 ID、工作区白名单、cwd、paths、unittest cases/pattern、
timeout 和 expected_cases。cwd/paths 必须是快照内相对路径。pytest 支持注册的
`tests/test_orders.py::test_cancel` 节点选择器；unittest cases 是限定测试名称。
完整定义、runner 资产、镜像和预算进入任务指纹。修改后同步重启 API/Worker，已提交
任务配置漂移返回 CONFIGURATION_CHANGED，不会改用新策略。

## 创建和查询

```bash
curl -X POST http://127.0.0.1:8002/v1/code/tasks \
  -H 'Content-Type: application/json' -H 'Idempotency-Key: cancel-analysis-1' \
  -d '{"stage":"analysis","task":"分析订单取消及异常处理，必要时运行相关测试","workspace_id":"project","target":{"kind":"workspace"},"context_task_ids":[],"check_suite_id":"project-python"}'

curl http://127.0.0.1:8002/v1/code/tasks/TASK_UUID
curl http://127.0.0.1:8002/v1/code/tasks/TASK_UUID/checks
curl http://127.0.0.1:8002/v1/code/tasks/TASK_UUID/artifacts
curl http://127.0.0.1:8002/v1/code/tasks/TASK_UUID/artifacts/ARTIFACT_UUID
curl -X POST http://127.0.0.1:8002/v1/tasks/TASK_UUID/cancel
curl http://127.0.0.1:8002/v1/tasks/TASK_UUID/timeline
```

指定本地提交时 target 使用 `{"kind":"commit","ref":"HEAD~1"}`。首次准备解析为完整
SHA，随后不再解析移动引用。工作区目标默认包含 tracked 当前内容、删除/执行权限、
原始 index 和非忽略 untracked 普通文件；staged/unstaged 区别保留。提交目标从原始
树和 blob 生成源码及干净 index，无 checkout/filter。两种目标均使用独立 Git 对象
副本、固定本地引用和最小配置，不复制 hooks、凭据配置、reflogs 或共享可写对象。

context_task_ids 最多 8 个，须同工作区的新代码分析任务；复用 Task 等待和失败传播。
历史报告仅是外部上下文，不能替代当前源码读取。所有请求字段参与幂等摘要。
stage 除 analysis 外返回 422。客户端不能指定分析 Profile；从通用入口使用
code-analysis-isolated 返回 CODE_TASK_REQUIRED。

## 报告与检查语义

AnalysisReportV1 包含范围、实现位置、调用关系、行为结论、执行/异常路径和未确认项。
read_file/git_read_file 返回 evidence_id、摘要和实际返回的完整行号；搜索只能定位。
引用须归属本 Run/快照，行号须已读取，index/历史 commit 须明确标记来源。
结构或引用错误由 ToolStrategy 在同一图内反馈，仍消耗原预算。

服务端补充任务、Run、快照、提交、检查摘要和正式产物 ID，并渲染 Markdown。
结构化 JSON 中的 authority 是服务端字段。模型不能覆写真实检查结果；Markdown
末尾始终插入服务端检查状态。证据校验保证记录和引用真实，**不自动证明模型推断
的语义正确**。项目测试仍是项目提供的代码，不等于独立可信业务规格。

两种 Python runner 分离日志与结构化通道；pytest 禁用环境插件自动加载、项目 addopts
及额外 CLI 参数，使用固定插件。源码只读，/tmp 可写，不生成源码 bytecode，缓存和
临时产物写 /tmp。没有网络、Docker socket、服务密钥或产物存储挂载。

- passed：完整、至少一项、协议一致，无失败、错误、跳过和缺少要求用例。
- failed：有效结果记录实际断言失败、测试错误或意外成功；同时保留覆盖限制。
- inconclusive：超时、OOM、依赖/收集错误、零测试、跳过、缺少要求用例、协议损坏
  或超限等。stdout 的“OK”及单独退出码不能制造 passed。

失败或 inconclusive 后 Agent 可以继续分析；Docker 失联、身份不明、失租、取消和
无法确认清理会终止 Run。一次 `(run_id, tool_call_id)` 只登记一个检查，不重放结果
未知的检查。检查日志在完成后即可于仍在执行的任务下下载；超时日志保留已接收部分。

## 预算、边界与恢复

默认模型 16 次、工具 32 次、检查 12 次；Run 300 秒，快照最多 60 秒/3 次尝试，
单次检查最多 60 秒，最后 30 秒预留清理和发布。全局限制可收紧。并行检查顺序执行，
共用总计数及截止时间。快照含对象副本最多 1 GiB、50,000 源码文件、单文件 10 MiB，
日志和检查结果各 1 MiB，模型报告 64 KiB。模型可见输出继续限制 16 KiB/200 行。
这些是接纳限制，不是宿主机磁盘硬配额；管理方需保证受管存储容量。

不支持外置 worktree、子模块、alternates、partial/shallow、split/sparse index、冲突
index、纳入范围的符号链接和特殊文件。不支持 Review 范围比较、编辑、修复、合并或
写回。封存文件或摘要缺失时失败，绝不退回原目录。未配置检查集时允许静态报告，
明确显示未配置、未执行。已配置但没调用时明确显示未执行。

主资源保留原工作区排他占用，execution_root 才指向封存快照。准备/检查容器另有
code_execution_resources 日志；create 前登记，start 前确认 ID，名称和租约标签核验
后才清理。所有容器 PID 1 使用绝对截止时间看门狗。容器 create 结果未知时保留占用，
不重复创建。`python -m db.doctor --json` 可列出未释放主/子资源和未知记录。

Worker 重启先核对和清理过期资源，不重放已中断 Run。Docker 暂不可用时未释放记录
仍占用容量/工作区，并阻止成功发布；恢复 Docker 后由 Worker 继续核对。不要手工
删除归属日志来解锁。最终报告先诊断暂存，与 Run 完成在同一数据库事务内正式发布。
失败、取消和失租产生的诊断产物不会被作为正式报告。

终态超过七天的快照、日志、报告可由 Worker GC 删除内容，查询元数据保留；活动依赖
和未释放资源阻止删除。已过期下载返回 410，不存在/跨任务返回 404；丢失或损坏
返回 409。下载按任务与产物 ID 查找，不接受路径或暴露宿主机存储键。
