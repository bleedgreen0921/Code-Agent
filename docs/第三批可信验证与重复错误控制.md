# 第三批：可信验证与重复错误控制

本批以 core_0007、413 项验收为基线，对应[总计划](异常处理与执行一致性增强计划.md)。新增 core_0008，仅增加可空的 `runs.verification JSONB`，不回填历史报告。独立验收见[验收记录](第三批可信验证与重复错误控制验收.md)。

## 注册与兼容

验证只能由可信 Python 构造 Extension，API、TOML、模型消息与远程工具注解都不能注册实现：

```python
from agent_service.profiles import Extension, Registry
from agent_service.verification import VerificationResult

async def verifier(context, candidate_answer, checkpoint_ref):
    # 合成示例；首版不提供真实测试、Lint 或构建业务。
    return VerificationResult(status="passed", summary="Synthetic verification")

registry = Registry(
    config,
    extensions={"project": Extension(
        version="2",
        verification_mode="required",
        verifier=verifier,
        verification_timeout=10.0,
        no_progress_enabled=True,
    )},
)
```

`verification_mode` 默认未配置，完全不调用验证器。`report` 缺少验证器时报告 `not_checked / verifier_not_registered`，允许正常完成；`required` 缺少验证器启动即拒绝。异步 callable 必须接受三个位置参数，超时必须是有限正数，重复错误开关必须是严格布尔值。没有模块路径动态导入。

启用的验证模式、超时、注册状态、Extension 版本同时写入冻结绑定和 Profile 指纹；重复错误策略的版本、三个白名单错误、三次阈值及子 Agent 隔离语义也进入指纹。两项均未启用时不增加绑定字段，保留 core_0007 绑定公式。实现行为改变须提升 Extension 版本；函数、资源与闭包不序列化。API 与 Worker 必须使用相同可信注册。

## 结果、上下文与覆盖

验证器必须返回严格且冻结的 `VerificationResult`，仅包含 status、summary、checks、reason。status 支持 passed、failed、inconclusive、not_checked。checks 是至多 16 项的 tuple，每项是 `VerificationCheck(status=..., explanation=...)`。摘要最多 1024 UTF-8 字节，每项说明最多 512 字节；reason 是有界的小写原因码。拒绝额外字段、类型错误、控制器元数据与超量结果。

控制器产生 `VerificationReport`，保存来源 Run、原生根 checkpoint 的明确引用、候选答案 SHA-256、绑定指纹、Extension 版本、模式、最终/阶段标志、开始/结束时间，以及真实文件观察。完整报告最多 32 KiB，数据库只接受对象并执行同一字节上限。报告不包含文件正文、命令参数或原始异常。

验证上下文是冻结的身份和候选数据，只提供共享剩余预算读取及 `await context.read_file(path, start_line=1, max_lines=200)`。读取返回冻结的 content、sha256、start_line、end_line、truncated。没有 Store、graph、checkpointer、可变 RunContext、ExecutionScope、Shell、MCP 或后台启动入口。可信 Python 仍可访问进程自身能力；该接口不是 Python 沙箱。

文件读取沿用 Profile 的 read_file 权限、可信参数 validator、原工作区 Docker、资源锁、大小限制和路径防护。控制器规范化路径，并记录执行 helper 对实际字节给出的哈希及实际返回行范围，最多 32 个文件、64 次观察，每个相对路径最多 512 UTF-8 字节；覆盖记录另有序列化容量预算，为最终报告预留空间。超出覆盖预算或安全地无法访问文件时报告 inconclusive；越权或非法参数则是契约错误，即使验证器捕获了访问异常也不能通过。

同一文件重复读取出现不同哈希，或结束时逐个受控复核发现修改、删除、类型变化、符号链接替换，报告变成 `inconclusive / workspace_changed`，覆盖 passed 和 failed，并保留已返回检查说明。复核无法完成、访问或报告容量不足也不能通过。部分行读取不代表检查了整文件；哈希只标识采样时的内容版本。空文件覆盖的合成验证器允许通过。验证结束后访问入口撤销；不保证之后文件持续不变。

## 完成边界、错误与事务

顺序为：原生 Agent 返回 → 确认最终 checkpoint → 关闭新的 Agent 动作 → 只读快照判断最终候选 → 验证和文件复核 → 清理 → 既有发布事务。验证仍在 Worker 续租、取消、本地租约监督和有效执行期限内，不占用清理或发布预留，也不进入数据库事务。验证器与文件复核共享 `min(verification_timeout, remaining_execution)`。

最终候选要求 Task 允许执行、无活动或未知后台操作、无其他 Run 遗留的相关工作区资源，且所有后台结果已消费或已按可信交付契约交付当前 Run。当前 Run 自有、等待本次清理的 Docker/MCP 资源不阻断验证。快照不拿 admission 锁，不维护或外部观察。活动操作、历史占用、未交付结果形成 `not_checked / stage_report`；取消、失租和未知事实仍失败。独立 Run 的同步外部结果未知也失败。

| 验证情况 | report | required 最终候选 |
|---|---|---|
| passed | 正常完成 | 正常完成 |
| failed | 正常完成并保留报告 | VERIFICATION_FAILED |
| 显式 inconclusive / not_checked | 正常完成并保留报告 | VERIFICATION_INCONCLUSIVE |
| 控制器本地超时、文件变化或复核不完整 | inconclusive，正常完成 | VERIFICATION_INCONCLUSIVE |
| 非法返回或越过访问契约 | VERIFICATION_CONTRACT_ERROR | 同左 |
| 未预期普通异常，含验证器自身 TimeoutError | VERIFICATION_EXECUTION_FAILED | 同左 |

有效执行期限耗尽始终 RUN_TIMEOUT；取消、失租、持久化、环境丢失及相应异常组保留控制语义。异常日志仅通过既有安全格式器输出类型与位置，不保存异常原文。没有验证重试、修复循环、解释结果的模型调用或额外最终生成，原始答案与消息状态不被改写。

发布事务复核报告的来源、原始答案哈希、checkpoint、绑定、模式和版本，重查最终候选事实，并原子发布 Run 状态/结果/报告/诊断、成功 checkpoint、消息来源、后台消费和 Task 状态。required 最终候选缺少合法 passed 报告不能成功。阶段快照即使在发布前变成最终条件，也不能被提升为已验证最终成功。清理、取消、租约与 Task 终态守卫仍优先。

失败 Run 的 result 与成功 checkpoint 保持 null；报告中的 checkpoint 是候选证据，不能成为成功来源。验证已通过但后续取消或清理失败，可以保留真实报告，Run 仍取消或失败。已经因失租终结的 Run 不补写报告。丢失提交确认时只重试数据库操作，并精确比较同一租约、报告、答案、checkpoint、错误和诊断；没有模型、验证器或文件复核重放。

## 消息继承与 Task 收敛

统一的来源判定用于发布、调度、Task 收敛和 Worker 前驱检查。未配置保持旧规则；report 的正常完成 Run 可继承，即使验证失败或无法确认；required 只有成功发布、报告有效且最终验证 passed 的 Run 可继承。

required 阶段 Run 可以发布 completed 阶段报告，但不更新 last_success_run_id，不成为后继 previous_run_id，也不消费本次已交付的后台结果。续 Run 使用更早合格 checkpoint，没有则从 Task 原输入开始，并继续获得未消费可信结果。最终通过时才原子消费。没有新增验证调度器，继续使用原队列、Task 总期限和最多五次 Run。

## 重复错误控制

默认关闭，只由可信 Extension 开启。原生 NoProgressMiddleware 位于摘要和下一次模型生成前。可信参数、权限及固定文件执行边界在生命周期内标记 INVALID_TOOL_ARGUMENTS、PERMISSION_DENIED、FILE_VERSION_CONFLICT；普通 artifact、远程文本、历史 checkpoint 不产生证据。

指纹为最终工具名、Hook 修改后的最终参数、可信错误码的规范 JSON SHA-256。对象键排序，保留值类型与数组顺序；调用/消息/Run ID 和时间不参与。无法规范化的不计数，不保存参数账本或把参数写日志。相同指纹连续三次，下一次模型调用前抛出 NO_PROGRESS，且不会触发该轮摘要。成功、其他错误、参数/工具/错误码改变都会打断或重启计数。并发批次完成后按模型声明顺序汇总，批次中的成功能打断连续错误。

根 Agent 的 NO_PROGRESS 结束 Run 且不验证。子 Agent 只隔离自身 NoProgress，返回带诊断和已有 checkpoint 线索的 SUBAGENT_NO_PROGRESS，父 Agent 可继续；子 Agent 不执行验证器。其他控制异常不被隔离。各根/子执行独立计数，不从继承消息恢复。Shell 非零退出、MCP 业务错误、状态查询和正常重跑不在白名单；原生调用限额仍保留。

## 查询与部署

Run 详情、列表和 trace 返回可选 verification。Task 详情在同一只读快照关联 current_run_id 的报告；当前 Run 尚无报告即 null，不借用旧报告。历史 null 只表示未记录验证。无新增验证触发、覆盖、重跑接口，提交请求、状态集合、答案和错误 envelope 保持原契约。

部署继续：停止旧 API/Worker → 备份 → owner 运行 db.migrate → db.bootstrap → db.doctor --json → 启动同一版本 API/Worker。保留 legacy 至 core_0007 全部结构签名；运行角色无 DDL。历史报告不回填、绑定不重写、失败任务不恢复、未确认占用不释放、工作区修改不回滚。框架依赖不升级。
