## 实施结果

- 在现有 StructuredTool 工厂注册 git_status、git_log、git_diff、git_read_file，每 Run 仍使用既有容器 helper、授权、工作区锁、资源预留、有效期限、日志、ToolMessage、checkpoint 及清理机制。
- 当前审查区分 HEAD → index、index → 工作区及未跟踪文件；暂存上下文直接读 stage 0 blob，历史上下文固定完整提交 ID。根提交使用 Git 原生根比较，合并提交明确第一父比较，删除文件可从确定的第一父读取。
- 所有 Git 调用固定 argv、关闭可选写锁、fsmonitor、外部 diff、textconv 及交互；有外部 clean/process filter 配置时保守拒绝当前状态和未暂存差异。暂存、历史只读取原始对象，不运行转换程序。
- stdout/stderr 流式有界读取，分页停止即回收子进程。正文与 artifact 均有来源和截断元数据，续读按实际完整输出计算。超长记录不会被跳过；不支持内容明确披露。
- Git 工具加入统一工作区工具集合及配置快照，未加入写工具集合。独立示例中的 Review 加四种工具，Fix 只加状态与 diff；Analyze、内置 Profile、子 Agent 范围保持兼容。
- helper、镜像标签、启动握手和绑定执行版本统一为 workspace-v2。未修改框架或依赖版本、数据库 core_0008、HTTP 接口、业务状态或 verification 语义。

## 部署边界

本次在验收环境重建了不可变 workspace-v2 镜像。生产部署需将构建输出的镜像 ID 与独立运行配置同步给 API/Worker，按既有流程检查和重启；没有擅自修改生产绑定或重启生产服务。不需要数据库升级。

仍遵守首版边界：工作区根必须为完整内部 .git 的仓库根；不自动挂载上级仓库、fetch 或修复缺失对象。外部 filter 拒绝范围是仓库级的保守判断；实时观察不是跨调用原子快照；超长记录不能读完时明确披露。验收使用合成模型，不表示真实模型的审查效果评测。
