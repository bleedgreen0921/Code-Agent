---
name: code-review
description: 只读审查指定代码、当前 Git 改动或历史提交中的行为问题。
---

按用户提供的范围读取目标代码和必要上下文，内容截断时按需分段读取。
优先检查行为错误、边界条件、返回值、异常处理和兼容性；风格偏好不作为确定缺陷。
每个确定问题说明位置、触发条件、影响及源码依据；将待确认疑问单独列出。
允许没有发现可确认问题，不为凑数量推断缺陷。
多步骤任务可用 write_todos，简单任务直接处理。

只读审查，不修改代码。工具权限由 Profile 决定，Skill 不授予权限。
指定代码审查可用于非 Git 工作区，不强制先调用 Git。
审查当前未提交改动时：先 git_status 区分暂存、未暂存、未跟踪和冲突；
分别 git_diff(source=staged/unstaged, view=files) 列出变更，再按文件读取 patch。
不能用一次 HEAD 到工作区比较替代这两个范围，即使二者互相抵消。
暂存上下文用 git_read_file(source=index)，工作区和未跟踪文件用 read_file。
同一文件同时出现于两个范围时，分别说明问题属于哪个版本。

审查历史时先 git_log 获取候选，选定后固定完整提交 ID；后续历史分页使用返回的 revision。
用 git_diff(source=commit) 列清单、读 patch，相关文件用 git_read_file(source=commit) 读取同一提交。
删除文件或旧版本上下文仅读取已确定的第一父提交，并标为旧版本，不使用当前工作区替代。
合并提交在结果中明确注明“第一父比较”；根提交使用工具的原生根比较。
仅要求历史时列候选供用户后续任务选择；目标不明且有多个候选时不声称已完成指定提交审查。
工具输出分页位置不是源码行号，问题定位使用 patch 的新旧行号。
实时状态不构成跨调用原子快照；来源变化时重读，明确范围变化。
冲突、不支持内容、截断或预算不足时列出尚未审查内容，不推断已完整覆盖。
引用已读取代码时使用工作区相对路径及实际行号，例如 src/example.py:12，不编造位置。
用户片段或变更说明未对应到文件时，标明证据来源，不虚构文件路径或行号。
未实际执行时，不声称运行、复现或验证过。

最终按以下 Markdown 二级章节输出：

## 审查结论
说明是否发现可确认问题及主要影响。

## 问题清单
逐项列出确定问题的位置、触发条件、影响和依据。
没有确定问题时明确写“未发现可确认问题”。

## 审查范围与未确认事项
说明模式、目标版本、比较基准、实际覆盖的文件或片段、遗漏范围和待确认疑问。
静态审查不能代替运行检查。
本 Profile 未接入可信最终验证，Run 完成不表示代码已通过正式验证。
