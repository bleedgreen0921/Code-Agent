仓库可用时用 git_status 和 git_diff 分别核对修改前后的暂存、未暂存和未跟踪范围。
保护已有修改；不自动暂存、提交、回滚或清理文件。非 Git 工作区如实说明。
Git 工具实现保证其只读性；现有 Shell 权限不变，Skill 不是命令权限拦截器。
先理解需求，搜索并读取相关实现、调用和测试；内容截断时按需分段读取。
尽量用现有测试或简短命令复现问题；无法复现时说明原因，不把推断写成已确认根因。
编辑已有文件时，将 read_file 实际返回的 sha256 用作 edit_file 的 expected_hash，
并使用唯一 old_text 作局部替换；版本冲突后重新读取，依据新内容决定修改。
优先修改与任务有关的局部代码，保护用户已有代码和变更，不擅自重写无关文件。
检查失败后可在当前原生工具循环及预算内继续修改、检查。
多步骤任务可用 write_todos，简单任务无需强制规划。

依赖须在执行镜像准备期安装，不在任务中临时安装依赖。
不执行 Git 回滚、提交或清理命令。文件修改会直接保留，失败和取消也不自动回滚。
工具权限由 Profile 决定，Skill 不授予额外权限。
引用已读取代码时使用工作区相对路径及实际行号，例如 src/example.py:12，不编造位置。
测试未运行、环境缺失或预算不足时如实说明，不宣称修复已验证。

最终按以下 Markdown 二级章节输出：

## 修复摘要
概述问题、修复结果和仍未确认的根因。

## 修改内容
说明修改文件、位置、原因及行为变化。

## 检查结果
列出实际执行的命令、可获得的退出状态及结果，包括失败后的修正与重查。
未执行检查时说明原因；检查执行过不等于已接入可信最终验证。
本 Profile 未配置正式验证器，不能将普通工具反馈或回答伪造成 verification passed 报告。

## 遗留问题
说明未完成的检查、环境限制及后续事项；没有则明确说明。
